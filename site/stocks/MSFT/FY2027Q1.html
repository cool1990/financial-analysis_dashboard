行业展望

外部环境（技术变化）

Satya 认为 AI 正在从追逐单个新模型转向企业真正把智能体系统落到业务流程里。他说过去那种“闪亮新东西”的热度在减弱，企业更关心能不能自己建系统、掌握权重、管理成本、保证可靠性和安全。

他把这比作过去企业建设数据库应用的阶段，认为现在企业 AI 应用正在进入类似的长期建设周期。Satya 强调这不是几个季度的事，而是十年维度的事，他更看重企业客户的广度，而不是少数几家大客户买大量算力带来的短期增长。

需求变化

Satya 说客户对 AI 服务的需求继续超过可用供给，这也是公司计划在第二季度把资本开支提高到 500 亿美元以上的原因。Amy 也确认，客户需求仍然大于供给，工程团队提升效率后，公司会尽量把新增容量优先分配给 Foundry。

需求正在从消费级尝鲜转向企业级智能体部署。Satya 举例说，联合利华在用全自动智能体系统处理订单和贸易券争议，劳斯莱斯用智能体管理包含 3 万个零部件的喷气发动机维护和供应链，奥地利银行 RBI 已经有 20 多个端到端业务流程在跑。

企业客户越来越倾向于多模型方案。Satya 提到，很多客户从前沿模型起步，但联合利华已经换上了用微软轨迹训练的 MAI 模型，说明客户在做模型优化、工作负载优化和 token 优化。过去一年，用多个模型构建智能体解决方案的客户数量增长了 5 倍。

供给变化

供给端的主要变化是工程效率提升和第三方交付延迟同时发生。Amy 说，第一季度工程团队在平台层做了很好的效率优化，不只是 GPU，还包括应用层、Foundry 和 Azure 平台本身，这让公司能把更多容量分配给 Foundry。

但她也说，一些原本预计第一季度到货的第三方容量被推迟，影响了资本开支和供给节奏。第二季度原本指望的部分供给也移到了下半年，所以公司需要继续靠工程效率来补上缺口。

Satya 强调公司把算力看成一个可灵活调配的池子，目标是让这个池子尽可能高效和 fungible。他说数据中心建设、上架速度、工作负载优化都围绕这个目标，然后根据需求信号决定把容量分配给 Copilot、Foundry、数据还是其他业务。

竞争变化

Satya 没有直接点名竞争对手，但他把竞争焦点放在成本效率和模型选择上。他说微软的目标是推进“成本到结果”的前沿，也就是在领先模型发布后 3 到 6 个月内，用低得多的训练成本提供可比能力，再把成本优势转给客户。

他举例说，MAI-Base-2 在测试中比其他开放权重模型的训练计算效率高 4 到 12 倍；MAI-Cyber 已经支撑超过 40% 的代码扫描，每次扫描成本低 18%；MAI-Transcribe 自称是世界上最准确、最便宜的转录模型。

在芯片层面，Maia 200 在 Teams 和 Copilot 的 AI 体验中每瓦 token 产出是之前系统的 1.7 倍，Maia 300 还会再提升 40%。这些效率提升被用来支撑 Azure 的供给和价格竞争力。

商业模式

Satya 说微软的商业模式正在从按席位订阅扩展到按用量计费，这会扩大总可寻址市场和每用户平均收入。订阅部分让每个用户都能用上越来越强的日常智能，通常由 IT 部门统一采购；而当智能体承担更高价值工作时，用量计费会打开由业务部门直接付费的需求。

他给出一个具体信号：通过用量计费积极消耗额度的 Copilot 客户数量在本季度增长了超过 75%。在 GitHub 上，智能体功能带来的额度消耗自用量计费生效以来已经翻了一倍多。

Satya 还解释了这种模式背后的逻辑：订阅把前沿能力普及到整个组织，用量计费则把支出和智能体实际创造的价值直接挂钩。他说这比只靠少数大客户买算力更像一门真正的生意。

公司战略

  1. 把 Copilot 打造成“新的工作操作系统”，把 Chat、Cowork、Autopilot 和 Code 统一到一个体验里，并内置 Office，目标是让用户真正用它完成工作。
  2. 围绕 Foundry 和 Fabric 构建企业智能体平台，让客户在数据旁边直接构建智能体，并用 Agent 365 做可观测性、用 Perception 做安全治理。
  3. 推进第一方模型和自研芯片，用 MAI 系列和 Maia 芯片降低训练和推理成本，把节省下来的成本转给客户，同时保持对 OpenAI 等前沿模型的支持。
  4. 把基础设施建成一个可灵活调配的算力池，加快数据中心上架速度，提升 GPU、CPU、存储和内存的整体效率，以应对需求大于供给的局面。
  5. 在 Windows 和设备端推动混合智能，让 PC 成为“安全的智能体盒子”，通过 MXC 执行容器和 Agent 365 把智能体治理延伸到端侧。
