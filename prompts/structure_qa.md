下面是业绩电话会 Q&A 的若干轮问答。把分析师的每个独立问题拆成一条记录，只输出 JSON 数组。同一轮里如果有两个互不相关的问题，输出两条，不要并成一句。

每条包含：
- exchange_id：输入中给出的编号
- analyst、firm
- topic：从话题清单中选；都不匹配时新建一个简短中文话题名，并把 is_new_topic 设为 true
- question_summary：一到两句中文，写清分析师真正想知道什么
- answer_summary：给投资者读的中文复述，说明这段回答对生意意味着什么。通常 3 到 6 句；内容多或有多位发言人时可以到 8 句。不要退回一两句空话，也不要逐字翻译整段原文。

  发言人写在每段开头。从该轮原文的发言人行读取姓名和职务（例如 `Name -- Chief Executive Officer` 或 `Name:`）。用名字、不必写姓；职务以文字稿为准，缩写放在中文括号里，例如 `Mark（CEO）`、`Susan（CFO）`。文字稿没写职务就只写名字，不要凭记忆补 CEO 或 CFO。认不出是谁才写 `管理层：`。能对上名字时不要写成「管理层表示」。分析师不是回答者。
  只有一位发言人时写成一段，以「名字（职务）：」起头。有多位发言人时每人单独一行，写在同一个 answer_summary 字符串里，用换行符 \n 分开；从第二位起可以写成「Susan（CFO）补充：」。不要用分号把两个人并成一句。
  用投资者读得懂的话解释判断和因果关系，不要把英文术语硬译成别扭的中文。例如 compute-intensive / compute-heavy 不要写成「服务计算密集」或「计算密集」，要写成算力消耗大、很吃 GPU，所以放量或全球上线要等效率和产能。The compute efficiency work is going to be important 不要写成空泛的「计算效率提升是关键」，要写清它卡住的是什么（还不能放量、要先达到能服务多少用户的效率、未来一年因此受限等）。各地优化、运行效率、产能是不同约束时分开写。只解释原文里有的意思。
  原文里的具体信息都要留下，不要为了写短删掉：用户数、地区、时间、产品名、免费层和付费层各用什么、产能或用户规模（例如十亿以上用户）、商业化是否要和降本同步、口径（GAAP、全年、下季），以及明确说了没有数字或不评论。上面这些只在原文出现时才写。没有的数字、产品、比例、时间不要编。

- new_numbers：回答中给出、但新闻稿里没有的数字，每项含数字原文和含义；没有则为空数组
- directness：direct（直接回答）/ partial（部分回答）/ evasive（回避）
- evasion_note：directness 不是 direct 时，写明没回答的是什么；direct 时为空字符串
- tone：positive / neutral / cautious（管理层回答的语气）
- answer_quote：从该回答里逐字摘 1 到 2 句连续原话，读得懂、能代表表态，优先保留关键数字。不要改写，不要截成半句，不超过 80 个英文单词。

写法示例（只示范分段和语气。示例里的事实不要写进别的问答；当轮原文没有的数字和产品名不要出现）：
"Mark（CEO）：最大的约束是这款产品算力消耗大，所以还没有全球上线。一部分是各地接入要单独优化，一部分是必须先把运行效率做上去，否则不能放量。算力要能服务他给出的用户规模，前提是先达到所说的效率目标，这会是未来一年的限制因素之一。\nSusan（CFO）补充：商业化要和降本一起做。目前没有可以对外拆开的单位成本数字。"

规则：
1. 只根据输入文本，不要补充外部知识，不要编造数字、产品或表态。
2. 没有分析师提问的开场、转接或结束语不要输出记录。
3. 某一轮如果确实无法概括，跳过该轮。不要用「文本不足」占位，question_summary 和 answer_summary 都不要写这四个字。
4. 输出 JSON 数组。这一批里如果没有任何可概括的问答，输出空数组 []。有真实提问时，每个提问都要有一条记录。
5. answer_summary 保持多句，并保留发言人和具体事实。不要为了缩短输出而改回一两句。
