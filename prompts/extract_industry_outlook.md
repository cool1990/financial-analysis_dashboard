行业展望：主要是总结 CEO 在电话会议正文中对行业的展望。忠实原文，通俗易懂，不要乱编造。格式是小标题加文字总结。

这一步在 GitHub Actions 的 Stage2 里由 DeepSeek 完成。页面直接渲染你的 JSON，不会再另写一版。写薄了，页面上就是薄的。

只输出一个 JSON 对象，不要 markdown 围栏：
{"topics":[{"title":"需求变化","blocks":[{"type":"p","text":"……"},{"type":"ul","items":["……"]},{"type":"ol","items":["……"]}]}]}

blocks.type 只许 p、ul、ol。p 用 text，ul 和 ol 用 items。没有的题目整题省略，不要写进 topics，也不要写「未提及」「无」。

题目只许这六个，按这个顺序。CEO 若把外部环境讲成技术变化，标题写成「外部环境（技术变化）」，括号里用他自己的角度，不要另起题目：
外部环境、需求变化、供给变化、竞争变化、商业模式、公司战略。

材料：
- 以 CEO 在电话会正文（prepared remarks）里的展望为主。
- CEO 在问答里把同一展望讲具体时，把数字、对比、条件和机制补进对应题目。
- 不要用 CFO 单独的一句财务口径代替某个题目。不要把分析师的假设写成公司的判断。
- 营收、利润率、EPS、资本开支的数字区间属于业绩指引，不要在这里复述区间。CEO 用数字说明需求、供给、竞争、收费或战略时，这些数字要留下。

写法：忠实原文、通俗易懂、勿编造。每题小标题加充分展开：有材料就写细，无则整题省略。优先保留数字、对比、因果和可执行的战略细节。

先看薄版为什么不能用，再看够用的密度。下面两段都是写法样例。样例里的公司、产品和数字只属于那一次电话会，换一家公司时禁止照抄。

薄版（不要写成这样）：
- 一题只有一句，含糊带过：「监管可能影响」「收入保持强劲」。
- 把 CFO 的一句竞争或变现口号当成整题。
- 丢掉数字、对比和机制，没有因果：看不出「因为什么，所以还不能做什么」。
- 六个题目各塞一句，凑满题数。

够用的密度（有材料时就写成这样，不要更短）：
- 每个有内容的题目是多段话，不是一句。先写 CEO 的判断，再写原因、证据和因此对公司意味着什么。
- 写出说话的人（用文字稿里的名，例如 Mark），不要写成「管理层表示」。
- 留下具体数字和对比：超过 1000 万人设置、约 25% 每天使用、客单价 200 美元以上、起步是 Threads 的两倍多、成本效率提升 10 倍以上、明年亏损约 150 亿美元。原文没有的数字不要编。
- 把机制写完整。例如：算力消耗大，所以还没有全球上线，要先把效率做上去才能放量。
- 需求要写来源（购物、效率、商家），商业模式要写清几种收费，公司战略若 CEO 列了几条做法，用有序列表，每条先写做法再写目标或原因。
- 用日常中文。不要逐句翻译，不要硬译英文术语，不要编造电话会里没有的产品、比例或结论。

规则：
1. 只根据输入文本。禁止补充电话会外面的知识。
2. 有材料就写细。一段话里要能看出判断、数字或对比、以及因果。材料只够一句、又没有数字和机制时，不要为了凑深度扩写，整题省略。
3. 禁止用「文本不足」「管理层表示」「保持强劲」这类空话占位。
4. 不要把六个题目都写上一句来充数。没有 CEO 原话支撑的题目直接删掉。
5. 公司战略如果是多条并行做法，用 ol；收费方式或并列机制用 ul；其余用 p。条目也要是完整的话，不要写成关键词。
